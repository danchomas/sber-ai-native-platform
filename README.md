# AI-Native BI

Платформа для исследования данных в диалоге. Пользователь загружает CSV или подключает базу PostgreSQL, задаёт вопрос обычным языком и получает ответ текстом, таблицей, графиком или готовым дашбордом.

- [Architecture.md](Architecture.md): текущая и идеальная архитектура, стек
- [Criteria.md](Criteria.md): результаты по сценариям и техническим критериям
- [TestCases.md](TestCases.md): прогон вопросов из `questions.txt` и ответы системы

## Что нужно

- Docker с Docker Compose
- `make`
- Ключ [OpenRouter](https://openrouter.ai) для модели `qwen/qwen3.8-27b`
- Свободные порты `3000`, `8080` и `5432`

## Запуск

```bash
git clone git@github.com:danchomas/sber-ai-native-platform.git
cd sber-ai-native-platform
cp .env.example .env
```

В `.env` укажите модель:

```dotenv
LLM_ENABLED=true
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=qwen/qwen3.8-27b
LLM_API_KEY=sk-or-v1-ваш-ключ
LLM_PROVIDER_ORDER=Near AI
```

Поднимите стенд:

```bash
make up
```

Первая сборка занимает несколько минут. Затем откройте **http://localhost:3000**.

Проверка готовности:

```bash
curl http://localhost:3000/api/v1/health
```

В ответе должно быть `"status":"ok"` и имя модели в `components.llm`.

## Загрузка данных

CSV можно загрузить на вкладке данных в интерфейсе или из каталога `./datasets`:

```bash
make datasets ONLY="01 09"   # «Продажи» и «Лекарственные препараты», как в TestCases.md
make datasets                # все наборы
```

Каталог `datasets` не входит в репозиторий, положите CSV туда перед запуском команды.

Базу PostgreSQL можно подключить напрямую в разделе источников: данные читаются на месте и не копируются.

## Первые вопросы

Откройте чат и спросите:

- «Что передо мной?»
- «Покажи наглядно, как распределена выручка по категориям товаров»
- «Создай дашборд с ежеквартальной статистикой продаж по федеральным округам»

Полный список вопросов и ответов находится в [TestCases.md](TestCases.md).

## Запуск с локальной моделью

Чтобы модель работала без облака, оставьте в `.env` значения из `.env.example` и выполните:

```bash
make up-llm
```

Команда поднимет Ollama и скачает модель из `LLM_MODEL`. Для `qwen2.5-coder:7b` нужно около 6 ГБ памяти. На локальной модели весь набор вопросов не прогонялся: качество ответов может отличаться от показанного в [TestCases.md](TestCases.md).

Если модель отключена (`LLM_ENABLED=false`) или недоступна, платформа продолжает работать и описывает данные по профилю каталога.

## Основные команды

| Команда | Что делает |
|---|---|
| `make up` | Поднимает PostgreSQL, API и интерфейс |
| `make up-llm` | То же плюс Ollama с загрузкой модели |
| `make down` | Останавливает стенд, данные сохраняются |
| `make logs` | Показывает логи API |
| `make test` | Запускает тесты Go, нужен локальный Go 1.27 |
| `make front-test` | Запускает тесты интерфейса, нужен Node.js |
| `make scenarios` | Прогоняет вопросы и атаки через API, нужен `jq` |
| `make scenarios-ui` | Проходит вопросы через интерфейс со снимками экрана |
| `make help` | Показывает все команды |

## Если что-то не работает

| Что происходит | Что сделать |
|---|---|
| Порт занят | Измените `FRONTEND_PORT`, `API_PORT` или `POSTGRES_PORT` в `.env` |
| `components.llm` не в статусе `ok` | Проверьте `LLM_API_KEY` и `LLM_BASE_URL`, затем выполните `docker compose up -d api` |
| Агент теряет параметры при вызове инструментов | Проверьте, что задано `LLM_PROVIDER_ORDER=Near AI` |
| Логи | `make logs` |
